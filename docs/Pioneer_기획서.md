# Pioneer 기획서

> 버전 v1.7.0 · 2026-06-29

---

## 문제 정의

**어떤 유저가:** 30분 이하의 짧은 자투리 시간에 게임을 즐기고 싶은 성인 전략 게임 팬
**어떤 상황에서:** 매번 비슷한 패턴이 반복되는 경영/전략 게임에 지루함을 느낄 때
**어떤 게임적 욕구를:** 한 번의 선택이 연쇄적으로 의미 있는 결과를 만들어내는, "내가 선장"이라는 통제감과 성취감을 원한다.

---

## 한눈에 보는 게임

| 항목 | 내용 |
|---|---|
| 한 줄 소개 | 항해, 교역, 선단 확장을 한 루프로 묶은 해상 경영 게임 |
| 핵심 재미 | 항구별 시세와 날씨를 읽고 항로를 선택하면 결과가 즉시 바뀌며, 성장한 선단으로 더 큰 교역이 가능해진다 |
| 30초 목표 | 현재 날씨와 항구 시세를 보고 최적 항로를 골라 출항한다 |
| 플레이 감각 | 상황 파악 → 의미 있는 선택 → 즉각적 피드백 → 다음 목표 제시가 끊기지 않는 흐름 |
| 현재 개발 상태 | v1.7.0 · React(Vite) + Electron portable 구조. 핵심 교역 루프, 항로 요약, 선단/교역 흐름 표시 구현 완료 |
| 구현 파일 | `src/App.jsx` (단일 파일, ~1,700줄) |

## 주 페르소나

**이름:** 박준혁 (가상, 34세, IT 스타트업 기획자)
**직업:** IT 스타트업 기획자
**현재 게임 습관:** 모바일 퍼즐·방치형 게임을 통근 시간(편도 30분)에 플레이. 주말에는 PC 전략 게임(문명류)을 즐기지만 2~3시간 세션이 부담스러워짐. "한 판이 너무 길거나 너무 단순한 게임은 금방 삭제한다."
**이 게임을 플레이하는 맥락:** 점심시간 15~20분, 잠자리 들기 전 10분 같은 짧은 세션에 활용. 선택 결과가 즉시 보이고, 다음에 뭘 해야 할지가 명확한 게임을 원함.
**기대하는 경험:** "내 배와 선원이 성장하는 게 보이면 또 켜게 된다"는 반복 플레이 동기. 내가 고른 항로가 맞았는지 틀렸는지 결과로 즉시 확인하는 구조.

## 핵심 루프

```
유저가 항구 시세와 날씨를 확인한다
  → 교역할 자원과 목적지 항구를 선택한다
  → 항해 중 날씨 이벤트와 조우 위험에 대응한다
  → 도착 후 매매 결과(이익/손실)를 확인하고 자원·선단을 성장시킨다
  → 새 퀘스트·일일 목표가 갱신되어 다시 항구 시세 확인으로 돌아간다
```

---

## MVP 가설

1. **[핵심 교역 루프]가 있으면** 한 항해를 완료한 플레이어는 결과를 보고 자발적으로 다음 항해를 시작하며 재시작률 60% 이상을 달성할 것이다.
2. **[위험/보상 동시 표시]가 있으면** 날씨와 가격이 동시에 보일 때 항구 선택 시간이 줄고 선택 납득도가 높아져 결과 불만 피드백이 20% 이하로 줄어들 것이다.
3. **[성장 보상 시스템]이 있으면** 세션 보상(선원·배 강화)이 다음 전략 선택을 바꿔 반복 플레이 피로가 낮아지고 3판 내 서로 다른 교역 루트 선택률이 50% 이상이 될 것이다.
4. **[퀘스트·일일 목표]가 있으면** 단기 목표가 제시되어 플레이어의 세션 중 이탈이 줄어 핵심 선택 화면 무응답·이탈률이 15% 이하가 될 것이다.

## 레퍼런스 분석

| 게임 | 핵심 행동까지 UX 단계 수 | 적용 교훈 |
|---|---|---|
| **Port Royale 4** (해상 경영) | 튜토리얼 8단계 → 첫 자유 교역 약 15분 소요: **8단계** | 규칙 설명보다 먼저 선택 가능한 상황을 보여줘야 이탈이 줄어든다 — Pioneer는 한 판 시작까지 3단계 이내를 목표로 한다 |
| **Patrician IV** (해상 교역 전략) | 초기 세팅 5단계 → 첫 수익 확인 약 10분: **5단계** | 이익/손실 결과를 즉시 숫자로 표시해야 판단 근거가 명확해진다 — 결과 화면에 금전 환산값 병기로 적용 |
| **Cultist Simulator** (카드 기반 경영) | 첫 카드 배치 1단계 → 결과 확인 30초 이내: **1단계** | 첫 선택을 단순하게 만들고 결과 화면에서 다음 개선 포인트를 바로 제안한다 — 항해 결과 화면에 다음 전략 힌트 자동 제시로 적용 |

**이 프로젝트 적용 교훈 핵심:**
한 판 시작까지 3단계 이내, 첫 의미 있는 선택(항구 선택)까지 30초 이내를 목표로 한다. 결과 화면에서 다음 전략 힌트를 자동으로 제시해 다음 판의 진입 장벽을 낮춘다.

## 소개용 핵심 메시지

Pioneer는 "가장 비싼 곳에 팔면 이기는 게임"이라기보다 "항해하면서 선장으로 성장하는 게임"이다. 플레이어는 매 항해마다 시세와 날씨를 보고 어떤 항구로, 어떤 자원을, 지금 출발할지 기다릴지 결정한다.

- 좋은 항로 선택은 즉각적인 이익과 퀘스트 달성으로 돌아온다.
- 폭풍 같은 위기도 화물 선택·타이밍으로 피해를 줄일 수 있다.
- 한 판의 재미는 "이번 항해로 선단을 얼마나 키울 수 있나"를 빠르게 판단하는 데 있다.

## 30초 플레이 흐름

| 순서 | 플레이어 행동 | 화면에서 보여야 하는 것 | 재미 포인트 |
|---|---|---|---|
| 1 | 현재 목표, 보유 자원, 날씨 상태를 확인한다 | 상단 HUD, 선단 현황, 퀘스트 진행 상태 | 지금 뭘 해야 하는지가 즉시 보인다 |
| 2 | 항구별 시세 차이와 날씨 속도 배율을 비교한다 | 항구 목록, 시세, 날씨 아이콘, 스파크라인 | 좋은 항로를 발견하는 순간 "이거다" 하는 느낌 |
| 3 | 목적지 항구와 교역 자원을 선택해 출항한다 | 선택된 항로 강조, 예상 소요 시간, 예상 이익 | 내 판단이 맞는지 긴장감이 생긴다 |
| 4 | 항해 결과(이익·손실·날씨 이벤트)가 갱신된다 | 결과 수치, 자원 변화, 퀘스트 진행 업데이트 | 선택 결과가 바로 보상 또는 손실로 돌아온다 |
| 5 | 금화·보석으로 선원·배를 강화하고 다음 퀘스트를 확인한다 | 강화 선택지, 다음 퀘스트, 일일 목표 현황 | 선단이 커지는 성장감과 다음 판에 대한 기대가 생긴다 |

## 게임 구성과 규칙 (GDD 요약)

### 항구 및 교역

| 항목 | 내용 | 구현/검토 메모 |
|---|---|---|
| PORT_SPECIALTY | 항구별 특산 자원 (구매 20% 할인 / 판매 20% 프리미엄) | london: 양모, lisbon: 포도주, antwerp: 다이아몬드, venice: 비단, genoa: 해산물, istanbul: 자수, alexandria: 향신료, dubai: 방향제, mumbai: 면화 |
| 가격 히스토리 | 최근 5회 시세를 스파크라인으로 표시 | 시세 예측 보조 — 불러오기 시 prices 재생성으로 히스토리 불일치 위험 있음 |
| 항구 선택 | 9개 항구 중 목적지 선택 | 현재 날씨 기준 상위 추천 항구 강조 표시 필요 |

### 날씨 시스템

| 날씨 | 속도 배율 | 확률 | 비고 |
|---|---|---|---|
| 잔잔 | 1.0× | 50% | — |
| 순풍 | 1.3× | 20% | — |
| 역풍 | 0.7× | 20% | — |
| 폭풍 | 0.5× | 10% | 화물 최대 20% 손실 (스태미나로 완화) |

### 퀘스트 및 일일 목표

| 유형 | 내용 | 보상 |
|---|---|---|
| 운송 | 특정 상품 N개를 특정 항구에서 판매 | 금화 |
| 탐험 | 새 항구 N곳 방문 | 금화 + 보석 1 |
| 무역 | 누적 판매액 N금 달성 | 금화 |
| 일일 운송 | 특정 상품 N개를 오늘 안에 판매 | 금화 + 보석 1 |
| 일일 항구 순례 | 새 항구 N곳 발견 | 금화 + 보석 1 |
| 일일 매출 목표 | 오늘 누적 판매액 N금 | 금화 |
| 일일 거래 횟수 | 오늘 판매 N회 완료 | 금화 |

### 저장/불러오기

| 항목 | 내용 |
|---|---|
| localStorage 키 | `pioneer_save` (saveVersion: `1.1`) |
| 저장 항목 | 금화, 보석, 선단, 선원, 퀘스트, priceHistory |
| 주의 | prices는 저장하지 않음 — 불러오기 시 초기 난수로 재생성 |

| 빌드/배포 | Electron portable로 공유 가능 | 배포 경로 보유 | 문서·실행파일·버전 정보가 서로 어긋나지 않는지 확인 |
| 코드 구조 | 기능별 모듈 분리 권장 | 단일 파일 (~1,700줄) | App.jsx 단일 파일이 신규 기능 추가 시 충돌 위험이 없는지 확인 |

### PR 체크리스트

- [ ] 항해 완료 후 이익/손실 결과가 즉시 화면에 표시된다.
- [ ] 날씨 이벤트가 속도 배율과 화물 손실에 정확히 반영된다.
- [ ] 항구별 특산품 할인/프리미엄이 시세 계산에 올바르게 적용된다.
- [ ] 퀘스트·일일 목표 진행 상태가 항해 결과와 동기화된다.
- [ ] 일일 목표가 자정에 올바르게 리셋된다.
- [ ] 강화 선택이 다음 항해의 실제 결과에 차이를 만든다.
- [ ] 저장·불러오기 시 선단·퀘스트·priceHistory 데이터가 유실되지 않는다.

### 🖥️ UX / UI
- **항구 선택 화면 정보 과부하:** 현재 9개 항구가 동시 노출될 때 시세 차이와 날씨를 한눈에 비교하기 어렵다 — 현재 날씨 기준 상위 3개 추천 항구를 강조 표시(배경색 분리)하고 나머지는 접기 옵션으로 숨겨 선택 피로를 줄인다.
- **퀘스트 달성 직전 알림 부재:** 퀘스트 목표의 80% 진행 시점에 "거의 다 됐어요!" 뱃지 또는 진행바 강조로 완료 동기를 즉시 환기시킨다 — 퀘스트 완료율이 낮은 이유가 인지 실패일 가능성 대응.
- **빈 상태(신규 플레이어 첫 화면):** 저장 데이터가 없을 때 빈 선단 화면 대신 "첫 출항 준비 완료" 온보딩 카드를 표시하고, 첫 항해 추천 항로(런던→리스본)를 자동 하이라이트해 30초 이내 첫 선택을 유도한다.
- **폭풍 피해 결과 표시:** 화물 손실량을 수치만 표시하지 않고 "양모 3개 유실 → -240 금화 기회손실"처럼 금전 환산값을 병기해 손실 체감을 명확히 한다.

### 💰 수익화 전략
- **보석 소모 가속 패스:** 현재 보석은 선원 강화에만 사용된다 — "항해 중 폭풍 회피권(보석 2개)", "시세 갱신 즉시 트리거(보석 1개)" 같은 즉각적 편의 소비 항목을 추가해 보석 소모 루프를 만든다. 짧은 세션 유저가 "이번 한 판만 더"를 결정할 때 마찰을 낮추는 데 적합하다.
- **선단 스킨 판매(일회성 구매):** 배 외관·깃발 스킨을 보석 또는 소액 결제로 판매 — 기능에 영향 없는 과금으로 전략 게임 팬 거부감이 낮고, 선단에 대한 소유감을 강화해 장기 리텐션에 기여한다.
- **광고형 보석 적립:** 세션 종료 직후 "광고 보기 → 보석 2개" 제안으로 무과금 유저 유지 — D1 리텐션 목표(30%)를 위한 진입 장벽 제거용.

### 📦 콘텐츠 확장
- **단기(1~2개월):** 항구별 고유 이벤트 카드 추가 (예: "런던 안개 - 항해 속도 0.8×, 세관 면제"), 날씨 이벤트 2종 추가(안개·폭우), 선단 규모 5단계까지 확장
- **중기(3~6개월):** 계절 시스템 도입 — 계절마다 특산품 수요가 변동해 장기 루트 최적화가 필요한 층위 추가. 경쟁 상인 NPC 1~2명이 같은 항로를 선점해 가격을 변동시키는 시장 경쟁 레이어 추가.
- **장기(6개월+):** 플레이어 간 교역 결과 리더보드(주간 최고 수익), 공동 퀘스트(여러 플레이어가 같은 항구에 물자를 납품해 보상을 나눔) 등 소셜 레이어 도입으로 D7 이후 리텐션 강화

### ⚙️ 기술적 개선
- **단일 파일(App.jsx ~1,700줄) 분리:** 현재 구조는 기능 추가 시 충돌 위험이 높다 — 항구/날씨/퀘스트/선단/저장 모듈을 각각 독립 파일로 분리하면 병렬 개발 속도가 향상되고 버그 격리가 쉬워진다.
- **prices 저장 제외 → 시세 예측 불일치:** 불러오기 시 시세가 재생성되면 priceHistory 스파크라인과 실제 현재가가 어긋나 플레이어 혼란이 발생할 수 있다 — 최소한 마지막 시세(prices)를 저장해 불러오기 시 히스토리와 연속성을 유지한다.
- **localStorage 단일 저장 → 슬롯 저장 지원:** 복수 저장 슬롯(최대 3개) 지원으로 다른 전략 시도 시 기존 진행 보존 — 3판 이내 다른 루트 시도율(KPI 50%) 달성에 직접 기여한다.
