# Pioneer AutoDemo 및 NAN 소개서 정렬 설계

**작성일:** 2026-08-08  
**대상 버전:** v1.9.0  
**상태:** 사용자 방향 승인 완료, 구현 전 명세

## 문제 정의

NAN 2026 제출 영상을 혼자 촬영하는 개발자는 게임 조작과 녹화를 동시에 수행하면서 클릭 실수, 장면 순서 변화, 시장 상태 차이 때문에 동일한 품질의 영상을 반복 촬영하기 어렵다. 기존 소개서도 기능과 개선 이력을 먼저 보여줘 심사자가 “왜 재미있는가”를 빠르게 이해하기 어렵다.

## 주 페르소나

- **이름/나이:** 오진우, 30대
- **역할:** Pioneer 1인 개발자 및 공모전 제출자
- **현재 행동:** portable 실행파일을 직접 조작하며 시장, 선원, 선박, 항로 화면을 녹화한다.
- **사용 맥락:** 녹화 도구를 켠 뒤 별도 조작 없이 안정적인 소개 영상을 얻고, 같은 흐름을 PDF에서도 설명하고 싶다.

## 승인된 방향

1. 별도 `Pioneer_v1.9.0_AutoDemo_portable.exe`를 만든다.
2. 실행 즉시 약 150초의 결정적 시나리오를 자동 재생하고 반복한다.
3. `Esc`를 누르면 자동 진행을 중단하고 현재 상태에서 자유 플레이로 전환한다.
4. NAN 소개서 MD·HTML·PDF는 A안인 플레이 경험 중심 구조로 개편한다.
5. AutoDemo 장면 순서와 소개서 설명 순서를 동일하게 맞춘다.

## 목표

- 실행 후 5초 안에 자동 시연을 시작한다.
- 150초 안에 시장, 거래 영향, 선원, 선박, 항로, 출항을 모두 보여준다.
- 실제 UI와 실제 게임 상태 변경 함수를 사용한다.
- 같은 시작 상태와 순서로 세 번 연속 완주할 수 있다.
- AutoDemo는 일반 저장 데이터를 읽거나 쓰지 않는다.
- 소개서 첫 장에서 “무엇을 판단하고 왜 긴장하는가”를 60초 안에 이해시킨다.

## 비목표

- 외부 마우스 매크로나 화면 좌표 클릭을 사용하지 않는다.
- 실행파일 자체에서 영상을 녹화하거나 인코딩하지 않는다.
- 1시간 시장 사건을 시간 압축해 실제 주기처럼 오해하게 만들지 않는다.
- 구현되지 않은 전투, 사기, 거래 능력 효과를 시연하거나 문서에서 주장하지 않는다.
- 상품 시장을 실제 주식 거래 시스템으로 표현하지 않는다.

## AutoDemo 사용자 경험

1. 촬영용 실행파일을 실행하면 1440x920 창과 고정된 AutoDemo 상태가 열린다.
2. 2초 준비 화면 후 자동 시나리오가 시작된다.
3. 우측 상단에 작은 `AUTO DEMO` 배지를, 하단에 현재 장면 제목 한 줄을 표시한다.
4. 마지막 장면 후 5초 요약 화면을 보여주고 처음부터 반복한다.
5. `Esc` 입력 시 400ms 안에 자동 진행을 멈추고 현재 상태에서 자유 플레이로 전환한다.

## 150초 시나리오

| 구간 | 장면 | 자동 동작 | 전달할 재미 |
|---:|---|---|---|
| 0-8초 | 세계 지도 | 준비된 함대와 29개 항구 노출 | 넓은 무역 세계 |
| 8-28초 | 시장 읽기 | 리스본 거래소와 가격 히스토리 열기 | 모의 주식처럼 타이밍을 읽는 판단 |
| 28-43초 | 즉시 거래 영향 | 양털 매입 후 가격·자금·화물 변화 노출 | 내 행동이 시장에 바로 반영 |
| 43-60초 | 시장 리듬 | 3분 소폭 변동과 1시간 사건 타이머 노출 | 세계가 계속 움직이는 긴장 |
| 60-80초 | 선원 구성 | 항해·수리·연료·물류 능력이 다른 선원 비교 | 누구를 어느 배에 태울지 고민 |
| 80-100초 | 선박 선택 | 빠른 소형선과 큰 화물선 비교 | 속도와 적재량의 트레이드오프 |
| 100-125초 | 항로 결정 | 예상 수익·시간·위험이 다른 목적지 비교 | 수익과 위험 사이의 선택 |
| 125-145초 | 출항 | 항로 확정 후 진행 HUD 노출 | 판단이 항해로 이어지는 보상 |
| 145-150초 | 요약 | 핵심 루프 한 줄 정리 | 다음 판단을 기대하게 하는 반복 |

## 구현 구조

### `src/autoDemo.js`

- 단계 ID, 시작 시각, 지속 시간, 표시 문구를 정의한다.
- 경과 시간에 따른 현재 단계와 반복 시점을 순수 함수로 계산한다.
- 중지 상태에서는 단계가 변하지 않도록 한다.

### `src/autoDemoState.js`

- 함대, 선원, 화물, 가격의 결정적 fixture를 생성한다.
- 실제 게임 데이터 구조를 사용하고 매번 같은 값을 반환한다.

### `src/App.jsx`

- `?autoDemo=1` 쿼리로 모드를 활성화한다.
- 각 단계에서 기존 거래, 패널, 항로, 출항 동작을 호출한다.
- AutoDemo 배지, 장면 제목, `Esc` 중지를 처리한다.
- AutoDemo 세션에서는 localStorage 저장과 자동 저장을 차단한다.

### Electron 래퍼

- 일반판은 기존 URL을 로드한다.
- 촬영판은 `/index.html?autoDemo=1`을 로드한다.
- 두 래퍼 모두 내장 HTTP 서버를 사용하고 `file://`을 사용하지 않는다.
- 재현 가능한 래퍼 소스와 패키징 설정을 저장소에 둔다.

## 소개서 A안 구조

1. **첫 장:** “지금 팔까, 더 멀리 갈까?”라는 판단 중심 한 줄 소개
2. **왜 재미있는가:** 정답이 바뀌는 시장과 플레이어 행동의 즉시 결과
3. **시장:** 3분 소폭 변동, 즉시 거래 영향, 1시간 대형 사건
4. **선원:** 실제 효과가 연결된 항해·수리·연료·물류 능력과 배치 고민
5. **선박:** 11종 선박의 속도·적재량·승원 규모 선택
6. **항로:** 예상 수익·시간·위험 비교 후 출항
7. **성장:** 거래 수익이 선원, 선박, 항구 해금으로 돌아가는 반복
8. **구현 증거:** 실제 exe 스크린샷, 테스트, portable 상태

‘주식’은 “실제 주식 거래”가 아니라 **모의 주식처럼 가격 흐름과 매수·매도 타이밍을 판단하는 항구 상품 시장**으로 표현한다.

## MVP 가설

| 기능 | 검증할 가설 | 검증 방법 |
|---|---|---|
| 결정적 AutoDemo | 수동 촬영보다 장면 누락이 줄어든다 | 무입력 3회 반복 |
| 장면 제목 | 처음 보는 사람이 판단 이유를 이해한다 | 각 장면 한 문장만 보고 시스템 설명 |

| 동일 순서 | 영상과 PDF를 함께 볼 때 메시지가 강화된다 | 장면/문서 순서 대조 |

## 레퍼런스 적용

- Steam 소개서 작성 원칙처럼 짧은 고유 가치 제안 뒤에 상세 기능을 배치한다.
- Sailing Era처럼 항구, 가격, 선원, 선박을 각각 나열하되 플레이어의 선택 결과로 연결한다.
- Offworld Trading Company의 시장 설명처럼 가격 변동을 장식이 아닌 의사결정의 중심으로 설명한다.
- Port Royale 4처럼 실제 게임 화면과 핵심 시스템 설명을 가까이 배치한다.

## 테스트와 검증

### 자동 테스트

1. 단계 경계에서 올바른 장면을 선택한다.
2. 150초 이후 첫 단계로 반복한다.
3. 중지 상태에서 시간이 지나도 단계가 바뀌지 않는다.
4. fixture가 항상 같은 값을 만든다.
5. 일반 모드에서는 AutoDemo 상태와 저장 차단을 사용하지 않는다.

### 실행파일 검증

1. AutoDemo portable을 세 번 실행해 무입력 완주와 반복을 확인한다.
2. 1440x920과 1280x800에서 HUD 겹침을 검사한다.
3. 시작, 시장, 선원, 선박, 항로, 출항 장면을 스크린샷으로 확인한다.
4. `Esc` 후 400ms 안에 단계 진행이 멈추는지 확인한다.
5. index와 JS/CSS/PNG가 내부 HTTP에서 200으로 응답하는지 확인한다.
6. 일반 portable에서는 AutoDemo가 시작되지 않는지 확인한다.
7. 개편 PDF를 페이지별 PNG로 렌더링해 잘림, 겹침, 깨진 글자를 검사한다.

## 성공 KPI

- 실행 후 자동 시연 시작 5초 이하
- 150초 이내 핵심 시스템 6종 노출
- 무입력 반복 3회 연속 성공
- 저장 데이터 변경 0건
- 장면 누락 및 HUD 겹침 0건

## 실패와 복구

- 패널 전환 실패 시 해당 단계를 한 번 초기화한 뒤 재시도한다.
- 리소스 로딩 실패 시 자동 재생 대신 원인과 재시도 버튼을 표시한다.
- 최소화 후 복구하면 현재 경과 시간에 맞는 단계 화면을 재구성한다.
