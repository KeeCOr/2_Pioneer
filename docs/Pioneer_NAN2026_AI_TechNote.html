요약

  • 게임 내부 AI형 시스템: 3분 소폭 가격 변동, 1시간 대형 시장 사건, 플레이어 거래 영향, 가격 히스토리를 결합해 반복 플레이의 예측 불확실성을 만듭니다.
  • 개발 과정 AI 보조: 데이터 구조 설계, 기초 코드 생성, 밸런스 수치 반복 검증, 로직 분리, 테스트 케이스 도출, 문서 정리에 이르기까지 개발 전 과정에 걸쳐 생성형 AI를 협업 파트너로 활용했습니다.
  • AI 생성 에셋: 선원·선박·항구 컨셉 이미지를 AI 이미지 생성 도구로 제작해 문서 및 인트로 비주얼에 직접 연결했습니다. 사운드 에셋도 AI 생성 도구를 통해 제작할 계획입니다.
AI는 단순 코드 완성 도구가 아니라 스펙을 코드로 전환하는 첫 초안 생성기, 실수를 찾아내는 두 번째 눈, 에셋을 빠르게 시각화하는 제작 파트너로 활용했습니다.

02 AI 보조 데이터 구조 설계
항구·상품 데이터 스키마

29개 항구와 8종 상품의 기준가·변동 범위·수수료율을 담은 초기 JSON 스키마는 AI가 생성했습니다.

{
  "portId": "lisbon",
  "name": "리스본",
  "region": "유럽",
  "goods": [
    { "id": "spice", "basePrice": 120, "volatility": 0.025, "fee": 0.03 },
    { "id": "cloth", "basePrice": 80,  "volatility": 0.015, "fee": 0.02 }
  ],
  "riskLevel": 1,
  "unlocked": true
}
AI가 제안한 volatility 필드는 소폭 변동 계산과 대형 사건 충격 비율 모두에 재사용됩니다. 단일 필드가 두 시스템을 연결하는 설계 덕분에 항구별 특성을 한 곳에서 관리할 수 있습니다.
선원 능력치 공식

선원 능력치가 운항 수치에 미치는 영향 공식 역시 AI가 초안을 제시했습니다.

// AI 제안 초안 → 개발자 조정 후 확정
const speedMultiplier = 1 + crew.navigation * 0.04;   // 항해 능력치
const cargoMultiplier = 1 + crew.logistics  * 0.06;   // 물류 능력치
const repairRate      = crew.repair * 2.5;             // 초당 선체 수리량
const fuelReduction   = 1 - crew.fuelEff   * 0.03;    // 연료 소모 계수

단순 덧셈이 아닌 곱셈 계수 구조를 AI가 제안한 덕분에, 선원이 여럿일 때 능력치가 과도하게 누적되지 않으면서도 체감 성장이 가능한 균형을 잡았습니다.

AI 보조 밸런스 수치 반복 조정

29개 항구·8종 상품·4종 선박에 걸친 수백 개의 수치를 수동으로 조정하는 것은 현실적으로 어렵습니다. AI에게 특정 플레이 시나리오를 입력하면 수치를 시뮬레이션하고 과도한 수익 구간을 잡아냅니다.

이 루프를 반복함으로써 전체 플레이 경로의 수익 분산을 유지하면서도 경쟁적이고 매력적인 항구 선택 전략이 성립하도록 밸런스를 잡고 있습니다.

03 AI 보조 핵심 모듈 구현
marketPrices.js — 시장 로직 분리와 초기 뼈대

초기에는 App.jsx 내부에 시장 로직이 혼재해 있었으나, AI는 세 가지 독립 책임으로 분리할 것을 제안했습니다.

// AI가 제안한 모듈 분리 초안
export function applyMinorFluctuation(prices, ports)           { /* 3분 소폭 변동 */ }
export function applyTradeImpact(prices, portId, goodId, qty)  { /* 거래 영향 */   }
export function applyMajorEvent(prices, ports)                 { /* 1시간 대형 사건 */ }

이 분리 덕분에 marketPrices.test.js에서 각 함수를 독립적으로 검증할 수 있게 되었고, 대형 사건이 거래 영향과 독립적으로 동작하는지를 단위 테스트로 확인할 수 있었습니다.

routeSummary.js — 인터페이스 설계

AI가 먼저 인터페이스를 설계하고 개발자가 구현을 채우는 방식으로 개발했습니다.

// AI 제안 반환 형식
return {
  estimatedProfit: number,         // 예상 순수익 (수수료 차감 후)
  travelTimeMin:   number,         // 편도 이동 시간 (분)
  riskLevel:       1 | 2 | 3,      // 위험 등급
  blockedReason:   string | null,  // 차단 사유 (선원 부족, 연료 부족 등)
  threatSources:   string[],       // 위협 원인 목록
};
인터페이스를 먼저 확정한 뒤 구현을 채우는 방식으로 개발했기 때문에, UI 레이어가 구현 세부사항에 의존하지 않았고 나중에 내부 계산 방식을 바꿔도 화면 코드를 건드릴 필요가 없었습니다.
React 상태 아키텍처 최적화

초기 구현에서 시장 가격, 함대 상태, UI 선택 상태가 하나의 useState 객체에 혼재해 3분마다 전체 리렌더링이 발생했습니다. AI는 상태를 세 레이어로 분리할 것을 제안했습니다.

const [marketState, setMarketState] = useState(/* 가격·타이머 */);
const [fleetState,  setFleetState]  = useState(/* 선박·선원·화물 */);
const [uiState,     setUiState]     = useState(/* 모달·선택·탭 */);
